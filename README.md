# Prototype: Ашет-шаблон для нового Channels-клиента

Это чистый шаблон для запуска нового клиента по образцу Ашет (контент-ассистент + редактор личного бренда в Telegram). Все технические ассеты скопированы из `../ashet-olga/` как есть — это проверенный костяк (Dockerfile/entrypoint.sh/companion.js/transcribe.js/recall_memory.js/edit_image.js/generate_image.js/generate_video.js/compose_video.js/generate_avatar_video.js/clone_voice.js/create_avatar.js).

CLAUDE.md — это **шаблон с placeholders**, не готовый системный промпт. Перед провижинингом его надо заполнить под клиента (заменить `[ИМЯ КЛИЕНТА]`, `[ИМЯ АССИСТЕНТА]`, `<SLUG>`, `<SLUG_UPPER>` и заполнить все `[FILL: ...]` блоки). Без готового CLAUDE.md скрипт провижининга сам откажется запускаться — это by design.

## Что осталось сделать, чтобы запустить нового клиента

Порядок строго такой — пункты 1-3 блокируют деплой, 4-7 настраивают поверх.

### 1. Заполнить CLAUDE.md (блокирует провижинер)

- Заменить все `[ИМЯ КЛИЕНТА]` на имя клиента, `[ИМЯ АССИСТЕНТА]` — на название ассистента (если не «Ашет»).
- Заменить все `<SLUG>` на `client_slug` (латиницей, через дефис, например `ivanov-smm`).
- Заменить все `<SLUG_UPPER>` на тот же slug в верхнем регистре с подчёркиваниями (`IVANOV_SMM`).
- Заполнить каждый `[FILL: ...]` блок под клиента — кто она/он, текущие задачи, тон, анти-примеры, темы.
- Проверить раздел «Ограничения на публикацию» — какие платформы реально подключены для этого клиента, не копировать вслепую текст про «Instagram подключен через Buffer».
- Решить, нужен ли раздел «Голос и видео-аватар клиента (HeyGen)» — если клиент НЕ давал согласия на клонирование, удалить его целиком.

### 2. Создать бота и получить токен

В `@BotFather` в Telegram — `/newbot`, получить токен вида `123456789:AAF...`. Этот токен нужен скрипту провижининга. Никогда не коммитить — только в `.env` (в .gitignore).

### 3. Запустить провижинер

```bash
./new_channels_client.sh <slug> <bot-token>
```

Скрипт сам создаст git-репозиторий, Railway-проект, сервис, домен, деплой и напечатает в конце точный список ручных шагов. **Не запускай без подтверждения от пользователя** — Railway-ресурсы необратимы и видимы клиенту.

### 4. Разовые ручные шаги (после деплоя)

Скрипт напечатает точный чеклист — пройти по нему по порядку:

- **Volume** (баг CLI, через веб-дашборд Railway).
- **OAuth-логин клиента + Telegram-пейринг** — клиент делает сам через веб-консоль Railway (реальный pty в браузере).
- **Регистрация в дирижёре** (`super_bot.py` на neurostaff) — добавить per-client health/quality jobs и обязательно вызвать `_check_channels_auth_expired` внутри `_quality_job` (общий детектор истёкшей OAuth, не копировать per-client).
- **`PUBLISH_GATEWAY_SECRET_<SLUG>` + `MEMORY_GATEWAY_SECRET_<SLUG>`** на neurostaff — уникальные секреты, не переиспользовать между клиентами.
- **Buffer-аккаунт** (если подключаем Instagram) — клиент создаёт сам, токен и `channelId` кладём на neurostaff с суффиксом `<SLUG>`.
- **Telegram-канал/Stories** — опционально, только по явному запросу клиента. Предупредить, что Stories = MTProto-сессия клиента = эквивалент пароля от личного Telegram.

### 5. Что НЕ делает этот прототип намеренно

- Не запускает OAuth-логин клиента — физически требует владения аккаунтом клиента.
- Не создаёт Telegram-пейринг — то же.
- Не добавляет Volume — баг Railway CLI (воспроизведено, не наша ошибка).
- Не регистрирует клиента в `super_bot.py` — это сознательно ручной шаг (при 3-м+ клиенте стоит обобщить на список клиентов, см. playbook § «Когда усложнять автоматизацию»).
- Не запускает `clone_voice.js` / `create_avatar.js` — разовая настройка HeyGen только по явному согласию клиента, не автоматизировано.

## Когда этот шаблон пересматривать

- При 3-м+ Channels-клиенте — обобщить per-client job'ы в дирижёре на цикл по списку (сейчас copy-paste `ASHET_*` переменных, см. `project_ashet_channels_bots.md`).
- При 5-м+ клиенте — стоит подумать о переходе от скрипта-провижинера (вариант A) к оркестратору поверх Railway API внутри `super_bot.py` (вариант B).
- При первом реальном вызове Telegram Stories у нового клиента — могут вылезти сюрпризы формата `media`/`privacy_rules` в `SendStoryRequest`, не только копипаста.
